# Quality and revisions

## Apply learned corrections during production

Treat these as prevention rules, not a request for a separate feedback report or mandatory manager review. Adapt project-specific choices to the current brief.

| Recurring concern | Production rule | Enforce during |
| --- | --- | --- |
| Generic, AI-looking deck | Use brand-specific evidence, genuine assets, concrete choices and purposeful layout variation | Blueprint and design |
| Complex paid-media language | Use familiar words and explain the commercial meaning | Copy |
| Topic-only headers | Put the supported takeaway in the title | Blueprint |
| Tables on every slide | Select the visual by the slide's job | Blueprint/design |
| Weak use of ad evidence | Show relevant, readable observations beside interpretation | Research/design |
| Scope drift | Trace core slides to the brief or an essential decision | Intake/narrative |
| Overloaded opening | Keep the objective clear; move supporting detail to its chapter | Narrative |
| Audience mixed with execution | Profile cohorts, including relevant location, before mapping environments | Audience/narrative |
| Arbitrary platform choices | Cite the audience signal and explain the role | Media qualification |
| Repeated/fragmented slides | Merge when the thought is the same and readability improves | Header pass |
| Detail before rationale | Put architecture and partner logic before detailed delivery | Narrative |
| Ideas difficult to picture | Show the placement, interaction or storyboard | Execution |
| Product barely recognizable | Show exact product name, artwork, benefit and moment of use | Execution/design |
| Unclear integration timing | State duration/window or a labelled planning condition | Feasibility |
| Unspecified event or series | Verify the property and date or mark it proposed | Research/feasibility |
| Hero idea disconnected | Propagate it through partners, budget, timeline and summary | Dependency pass |
| Wrong names/logos | Check spelling and original assets | Asset review |
| Visual revision changes strategy | Lock content/order and compare before delivery | Revision pass |
| Removed content returns | Use the latest approved deck and explicit exclusions | Intake/final pass |

Ask five questions of every important slide: why is this here; what supports it; what should the client understand; what happens in practice; what changes elsewhere?

## Run six final passes

1. Brief coverage: requirements, format/count, priorities and exclusions.
2. Evidence: support, data periods, markets, denominators and visible uncertainty.
3. Story: coherent header sequence, useful order, clear choices and standalone comprehension.
4. Commercial/math: consistent spend, delivery, units, definitions, dates and confirmation status.
5. Visual/technical: every slide rendered/inspected, readable, accurate, openable and editable as requested.
6. Revision integrity: compare against current approved copy, order, numbers, sources and exclusions.

Fix issues at their origin and propagate changes. A changed allocation affects model totals, scenario comparisons, headlines and the close. A removed partner affects role coverage, executions and timing. Keep a private issue log with status and affected IDs; do not substitute a critique for completing the deck.

For visual-only revisions compare extracted text slide by slide and preserve sources/order. For strategic changes document affected dependencies and update them intentionally. Flag material unresolved execution dependencies concisely at handoff; proposed inventory can remain proposed in a finished strategic pitch.
